Real App Production Use Cases of Shell Scripting 

- Shell scripts(like deploy.sh, build.sh, moniter.sh) are the invisiable hands that automate and glue together your app's lifecycle. 
- Let's walk through each use case with mini real-world examples, especially relevant for C++ projects in production. 

1. Build Automation 
Task: Compile your C++ project on a build server 
Example: build.sh 
#!bin/bash 
echo "Starting Build..."
mkdir -p build 
cd build
cmake ..
// cmake: the command-line tool
 - CMake is a build system generator.
 - It reads CMakeList.txt files (project build scripts) and generate build files for platforms like Make, Ninja, Visual Studio, etc. 
.. // : The parent directory 
 - .. means:"go up one diretory" (the parent of the current directory)
 - So cmake .. means:
    "Run CMake and look for the CMakeLists.txt file in the parent directory."
make -j$(nproc) 
// make 
  - This command builds your project (usually after running cmake).
  - it reads the Makefile generated by cmake
// -j 
  - Tells make to run jobs in parallel 
  - Great for speeding up compilation on multi-core systems.
// $(nproc) 
   - This runs the nproc command inside make.
   - nproc returns the number of CPU cores on your machine. 
   Example:
   If you machine has 8 cores, nproc returns 8, so the full command becomes:  make -j8 
   This runs 8 compilation jobs at once - much faster than doing one at a time    

Used in: CI/CD pipelines, or when developers run ./build.sh locally to ensure consistency.

2. Testing Automation 
Task: Run all unit testts (Google Test, Catch2, etc.)
Example: run_tests.sh 

#!/bin/bash 
echo " Running unit tests..."
./build/ticket_test 
if [ $? -eq 0 ]; then 
   echo "All tests passed"
else 
   echo "Some tests failed" 
   exit 1
fi 

Used in:
CI Systems like GitHub Actions, GitLab CI, Jenkins, etc 

3. Deployment Automation 

Task: Copy built binaries to a remote server.
Example: deploy.sh 

#!/bin/bash 
echo "Deployment to production server"

scp ./build/ticket_app user@yourserver.com:/opt/ticket_app/
ssh user@yourserver.com 'sudo systemctl restart ticket_app.service'

Used in:
Manual or semi-automated deployments 

4, Log Rotation/Archiving 

Task: Clean old logs to save disk space 
Example: rotate_logs.sh 

#!/bin/bash 
echo "Rotating logs..."
find /var/log/ticket_app/ -name "*.log" -mtime +7 -delete 

Used in:
Production servers(via cron jobs) to prevent full disks.

5. Monitoring / Health Check 

Task: Check if the app is running or healthy 

Example: health_check.sh 

#!/bin/bash 
echo "Checking ticket app..."
if pgrep ticket_App > /dev/null; then 
// ticket_App is usually the name of the executable (process name) 
// pgrep ticket_App : Finds and returns PIDs of all processes whose name matches ticket_App
   echo "Running"
else 
   echo "Not running! Sending alert..."
   echo "Ticket App Down" | mail -s "ALERT" admin@example.co machine

Used in : Monitoring systems or cron every 5 mintues 


6. Backup Automation 
Task : Backup database or app config daily 
Example: backup.sh 

#!/bin/bash 
echo "Backing up..."
tar czf /backups/config_$(date +%F).tar.gz /etc/ticket_app/ 

Used in:
Production or staging servers vis scheduled cron jobs 

7, Combining All in one Master Script 

You can combinal all these into one master pipeline:

#!/bin/bash 
./build.sh || exit 1
./run_test.sh || exit 1
./deploy.sh | exit 1
./health_check.sh 

Summary Table (Spoon-Fed Style):

Task - Shell Script Name - Triggered by - Role in Real App 

compile app - Build.sh - Developer/CI - Builds your project 
Run tests - run_tests.sh - CI pipeline - Ensures no bugs 
Deploy to server - deploy.sh - CI/CD or manual - Sends app to prod/staging 
Monitor app - health_check.sh - Cron/ monitoring - Detects downtime 
Archive logs - rotate_logs.sh - Daily cron - Prevents storage overflow 
Backup configs - backup.sh = Nightly cron - Protects from config loss
