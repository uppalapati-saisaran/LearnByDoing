union in dbms 
- union clause used to combine the result-set of two or more select queries.
- Applying union between single column
   select city from country1 union select city from country2 ==> if duplicate values present, it will display only once. 
- The columns used in all the select statments must have the following.
  - the same number of columns
  - similar or compatible data types.
  - same logical order 
- Selecting more than one column in the select query 
  - Whenever more than one column is specified in the select clause then the combination of all the columns considered that
    is if both the values in rows same then only this considered as a duplicate value
	
union all:
- union removes duplicate values while comparing where union all allows duplicate values when combining.
  select city from sample1

Indexing and Query Optimization 

Why?
- Indexing improves the speed of searches, joins, and WHERE filters.
- Without indexes, queries scan the full table(slow) 

Types of Indexes :

PRIMARY KEY - Unique and not null; only one per table. 
UNIQUE - Must contain unique values.
INDEX/KEY - Normal Index, can have duplicates.
FULL TEXT - For text searching (used in MATCH AGAINST)
SPATIAL - For GIS data (geometric types)

- Create a Sample Table 
CREATE TABLE employees(
     id INT PRIMARY KEy AUTO_INCREMENET,
	 name VARCHAR(100),
	 dept_id INT,
	 salary DECIMAL(10,2),
	 joining_date DATE
);

Now assume you have 100,000 employees and you run:

SELECT * FROM employees WHERE name = 'Sai Siran' 

Problem:
Without Index, MySQL scans all 100,000 rows line by line.

Add an Index :

CREATE INDEX idx_name ON employees(name);

What happens now?
MySQL creates a fast-lookup structure to quickly find rows with name 'Sai Siran'.

Check if Query Uses Index 

EXPLAIN SELECT * FROM employees WHERE name = "Sai Siran";

Excepted Output(simplied): |id|select_type|table|type|key | key_len|ref|rows| Extra |
                           |1 | SIMPLE | employees | ref | idx_name | 303 | const | 1 | Using where |
						   
You'll see output like this:
Key                   rows                Extra 
idx_name              1                   Using where 
						   
"key" column shows: idx_name is used -> Fast search!

Multi-Column Index :

If you often query:
SELECT * FROM employees WHERE name = "Sai Siran" AND dept_id = 2;

Create a multi-column index:
CREATE INDEX idx_name_dept employees(name, dept_id);

Best Pratices:
- Index columns used in WHERE,JOIN,ORDER BY, and GROUP BY
- Don't over-index (each index takes storage and slows inserts).
- Use explain to verify performance

1, Subqueries in MySQL 

- A subquery is a query inside another query. It's enclosed in parentheses and can return: A single value, A row, A table.

1.1 Subquery in SELECT 

- Show each employee's salary as a percentage of the total salary.

SELECT 
    name,
	salary,
	ROUND((salary/(SELECT SUM(salary) FROM employees)) * 100,2) 
  AS percent_total 
  FROM 
    employees;
	
1.2 Subquery in WHERE 

- SELECT name, salary
  FROM employees
  WHERE salary > (SELECT AVG(salary) FROM employees);
  
1.3 Subquery in FROM (Derived Table)

- SELECT dept_name, avg_salary 
  FROM (
    SELECT department AS dept_name, AVG(salary) AS avg_salary
	FROM employees 
	GROUP BY department
  ) AS dept_avg 
  where avg_salary > 60000;
  
1.4 Correlated Subquery (Row-by-Row Execution)

- Get employees whose salary is above the average of their own department.

SELECT name,department,salary 
FROM employees e 
WHERE salary > (
SELECT AVG(salary) FROM employees
WHERE department = e.department
);

What is a View?

- A view is a virtual table based on the result of the SELECT query. 
-It doesn't store data, but lets you reuse complex queries as if they're a regular table.


Why use views?

- Simplify complex joins/queries 
- Improve readability
- Enforce access control (hide sensitive columns)
- Reuse business logic 


1, Create a view 

CREATE VIEW high_earners AS 
SELECT name,department, salary 
FROM employees 
WHERE salary > 60000;


2, Use the View 

SELECT * FROM high_earners;


3, Update a View 

CREATE OR REPLACE VIEW high_earners AS 
SELECT name, salary 
FROM employees
WHERE salary > 70000;

4, Drop a View 

DROP VIEW high_earners;

Types of Views 

- Read only Views 
  If the view includes joins, aggregates, or subqueries, it's not updatable.
  
- Updatebale views 
  If based on a single table without GROUP BY, DISTINCT, etc,, It can be updated.
  
CREATE VIEW hr_employees AS 
SELECT id,name 
FROM employees
WHERE department = 'HR';

- Update through the view 
UPDATE hr_employees SET name = 'Alice Smith' WHERE id = 1;

View Limitations:

- No indexes on views.
- Views can't accept parameters (not like stored procedures)
- Performance: Each view query runs every time it's accessed.
