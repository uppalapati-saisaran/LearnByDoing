5, What is the difference between WHERE and HAVING?
A,

- WHERE filters rows before grouping 
- HAVING filters groups after aggregation 

SELECT department, COUNT(*) FROM employees
WHERE salary > 3000 GROUP BY department HAVING COUNT(*) > 5;

1. Look at the employee table. 
you're starting with a table called employee, which has information about workers - like their department, salary etc

2. Only picks employees who earn more than $3000.
This part: where salary > 3000
says: "Only look at employees making more than $3000."

3. Group them by department.
GROUP BY department 

says: Now, take those employees and sort them into groups based on which department they belong to.
so if there are 3 departments - HR,IT, Sales - you now have 3 groups.

4. Count how many employees are in each group 
SELECT department, COUNT(*)

means: For each department, show the department name and how many employees ( who earns > $3000) are in it.

5, Only show departments that have more than 5 such employees.
This 
HAVING COUNT(*) > 5 
means: Don't show department unless they have more than 5 employees making over $3000

Finaly Summary: Show me each department that has more than 5 employees earing over $3000, and tell me how many such employees are in each.

6, What are joins in MySQL? Explain types.

A, Joins are used to combine rows from two or more tables based in a related column.
Types:
- INNER JOIN: Returns records the match in both tables.
- LEFT JOIN: Returns all records from the left table, even if there is no match in the right.

- FULL JOIN: Not supported natively in MYSQL but can be simulated using UNION.

7, What is indexing? How does it improve performance?
A, An index is a data structure that improves the speed of data retrieval.
Explanation: When you query with a WHERE clause or join, MySQL can use the index to quickly locate rows
instead of scanning the whole table.

Example:
CREATE INDEX idx_emp_name ON employees(name);
// CREATE INDEX: This tells the database to make a shortcut.
// index_name: you give the index a name (it can be anything like idx_employeee_name)

What Does an Index do?

An index is like a book's table of contents. Instead of searching every page, you jump directly to where you need to go.
so if you often search for employees by name:

an index on name will make this much faster, especially if the table has thousands of rows.

8, What is normalization?
A, Normalizaion is the process of organizing data to reduce redundancy and improve integrity. 
- Data integrity in a database means ensuring that the data is accurate, consistent, and reliable through its entire lifecycle. 

Forms:
- 1 NF : Atomic values, no repeating groups.
- 2 NF : No partial dependecny
- 3 NF : No transitive dependency 

Example: Splitting a table with employee and department info into two separate tables to avoid repetition.

- Normailization breaks down a table into smaller tables to eliminate redundancy and improve data integrity.

Instead of:
employee(emp_id, name, dept_name)
Normalize to:
department(id,dept_name)
employee(emp_id,name,dept_id)

9, Difference between TRUNCATE, DELETE, and DROP?
A,

Operation       Deletes Data        Can Rollback             Affects Structure 

DELETE          Yes(rows)           Yes(If in transcation)   No 

TRUNCATE        Yes(all rows)       No                       No 

DROP            Yes(table)          Mo                       Yes 

DELETE FROM table_name 
// specifies the table from which you want to delete rows 
WHERE condition; 
// specifies which rows to delete based on a condition. Without WHERE, all rows in the table will be deleted!

TRUNCATE TABLE table_name 
What does it do?
- Deletes all rows from a table quickly.
- Resets any auto-increment counters(like primary key IDs).
- Does not log individual row deletions, so it's faster than DELETE.
- Keeps the table structure and its indexes intact - you can still insert new data after trunation.

DROP TABLE table_name;

What does it do?
- Permanently deletes the entire data from the database.
- This includes all the data, the table structure, indexes, triggers, constraints, everything.
- Once dropped, the table cannot be recovered unless you have a backup.
- Use with cautions

12, Explain transcations in MySQL?
A, A transcation is a set of SQL operations that are executed as a single unit.

ACID properities:
- Atomicity: All or nothing
- Consistency: Valid state 
- Isolation: No Interference
- Durability: Persisted after commit 

Example:

START TRANSCATION;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;

Scenerio 1 : Employee with the Highest Salary 

Problem: You have a table called employees:  Find the employee(s) with the highest salary. 

SELECT name,salary 
FROM employee 
WHERE salary = (SELECT MAX(salary) FROM employees); 

Explanation:
1, (SELECT MAX(salary) FROM employees ) -> finds the highest salary (e.g., 90000) 
2, WHERE salary = ... -> check which employee(s) match that value.
3, Returns:
   name     salary 
   Diana    90000 
   
- Handles ties (if two employees have the same highest salary, both are shown). 

SQL Query 2 (Alternative, Using ORDER BY) 

SELECT name,salary 
FROM employees 
ORDER BY salary DESC 
LIMIT 1; 



Explanation:
- ORDER BY salary DESC -> sorts from highest to lowest.
- LIMIT 1 -> Picks the first row (highest)
- Faster when you only want one result, but does not handle ties unless you change it.

- Gets top 3 employees with highest salaries.
- If salaries are tied, it just picks 3 rows, not distint salary levels. 

Advanced (With Window Functions) 

SELECT name, salary 
FROM (
     SELECT name, salary, DENSE_RANK() OVER (ORDER BY salary DESC) AS rnk 
     FROM employees 
) AS ranked 
WHERE rnk <= 3 

- DENSE_RANK() ensures ties are handled.
- Example: if two employees both have 90000, they both get rank 1, and the next salary (80000) is rank 2.

FROM employees

	  FROM employees 
	  WHERE salary < (SELECT MAX(salary) FROM employees) 
);

3, MAX(salary) again -> finds the highest from the remaining salaries.

1. WITH ranked AS(...) -> create a named temporary result(CTE) ranked to hold intermediate results.
2, SELECT emp_id, name, department_id, salary, -> choose the columns we need for final output and ranking.
3, RANK() OVER (PARTITION BY department_id ORDER BY salay DESC) AS dept_rank - windows function:
   - PARTITION BY deparment_id restarts ranking for each department.
   - ORDER BY salary DESC gives highest salary rank 1.
   - RANK() gives the same rank to ties (multiple people with same top salary get rank 1).
4, Outer SELECT ... FROM ranked where dept_rank = 1 - pick only top-ranked rows per department,rturning ties when present. 

When to use this pattern.

- Use when you want top N per group and must preserve ties.
- Works will on MySQL 8+ , PostgreSQL, SQL Server, Oracle. 

Performance & tuning (spoon fed)
- Index: create a composite index on (deparment_id, salary) to help ordering/grouping:
    CREATE INDEX idx_emp_dept_salary ON employees(department_id, salary DESC); 
- EXPLAIN the query to ensure optimizer uses the index.
- If the table is huge and this query runs frequently, consider a materialized result(e.g.,maintain a dept_top_earners table refreshed nightly).
- If department cardinality is low, scanning may be cheap; otherwise partitioned by deparment_id may help for very large tables.

Edge cases & notes:
- NULL salaries: decide policy (treat as 0 or ignore). Add WHERE salary IS NOT NULL inside CTE if you want to ignore NULLs.
- If you want exactly one top row even when ties exist (break ties deterministically), use ROW_NUMBER() with a tie-break column.

2) Percentage of Total Salary Contributed by Each Employee -- advanced (accurate with window functions)

Query(single pass, window function)

SELECT
   emp_id,
   name,
   salary,
   ROUND(salary * 100.0/SUM(salary) OVER(),2) AS salary_percentage 
FROM employees 
WHERE salary IS NOT NULL;

Spoon-fed explanation:

1, SUM(salary) OVER() - window function with empty parition, computes the sum across the entire result set (total payroll) in the same query, avoiding a separate aggregation subquery.
2, salary * 100.0 / SUM(...) - compute contribution as percentage. Multiply by 100.0 to force floating arithmetic.
3, ROUND(...,2) - format to two decimal places for readability.

Performance & tuning:

- this is one table scan and often more efficient than salary/(SELECT SUM(...) FROM employees) if optimier cannot reuse results.
- Ensure salary column type supports decimal arithetic (DECIMAL recommended for money).
- If you must exclude certain employee states (e.g. terminated), add a WHERE status='active' filter - then the winodw sum will be over active employees only.

Edge cases & notes:
- if total sum = 0, you'll get division by zero - protect with NULLIF:
  
  ROUND(salary * 100.0/ NULLIF(SUM(salary) OVER(),0,2) 
- if you want group-levl percentages (e.g., percent of dept total), use SUM(salary) OVER (PARTITIOB BY department_id).
